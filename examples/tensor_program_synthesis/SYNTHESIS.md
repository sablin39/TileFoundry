# Joint forward/backward residual synthesis

Implemented and validated using an isolated Python environment and pinned
TileFoundry commit `d933cf13d5600c97ec2f132a574bb7d62d6bdd56`.

## Run it

```bash
cd examples/tensor_program_synthesis
./test_synthesis.sh
./run_synthesis.sh
```

The default run solves MLP, compact-mask, and multi-chunk gated-delta-rule cases.
It writes selected plans, generated HIR, numerical validation errors, and complete
static-analysis reports:

```text
synthesis/graph.py           Pure tensor DAG, shapes, phases, availability, recipes
synthesis/planner.py         CP-SAT residual and recipe selection
synthesis/lower.py           Separate generated forward/backward HIR functions
synthesis/problems.py        Supplied MLP and chunk GDR forward/backward formulas
synthesis/validation.py      Independent numerical oracles
synthesis/test_synthesis.py  Search, mathematical, and emitted-HIR tests
synthesis/run.py             End-to-end experiment runner
generated/<experiment>/      Runnable authored TileFoundry modules
results/synthesis/<experiment>/joint_graph.json
results/synthesis/<experiment>/summary.json
results/synthesis/<experiment>/plan_*/plan.json
results/synthesis/<experiment>/plan_*/forward.json
results/synthesis/<experiment>/plan_*/backward.json
results/synthesis/<experiment>/plan_*/*.hir.txt
```

To rerun the larger, already validated experiment:

```bash
./run_synthesis.sh --case gdr \
  --length 65 --chunk-size 64 --key-dim 16 --value-dim 12 \
  --budgets 0,16384 --run-name chunk64
```

This is one 64-token chunk and a one-token tail, with nonzero initial state.
Use `--run-name` to retain a separate experiment when changing shapes or budgets.
`--skip-static-analysis` runs search and CPU HIR validation without allocation
and timing analysis. The full path is the default.

## What is automatic

The input is a supplied pair of forward/backward formulas, authored through the
small graph builder. Values shared by the phases are explicit graph edges. The
builder records shapes, dtypes, phase ownership, input availability, and common
subexpressions. Backward formulas are supplied; no AD system constructs them.

For each demanded value, the planner selects exactly one backward source:

- An externally available immutable input or ordinary forward output.
- A retained residual exported by forward.
- One reconstruction recipe, whose dependencies must themselves be available.

The search includes intermediate ancestors, not just the values directly named
by backward. Shared producers are charged once per backward invocation. The
solver minimizes a declared elementary-operation proxy under a **residual-byte
budget**, then minimizes saved bytes among equal-work solutions. Work includes
extra forward computations introduced to produce new residuals. A result marked
`OPTIMAL` is optimal for this bounded graph and cost model; `FEASIBLE` is reported
separately if a timeout leaves an unproven incumbent.

The recipe catalog currently includes one algebraic rule:
`positive(z) = positive(ReLU(z))`, with derivative zero at zero. The rule is
supplied; the solver decides whether to use it. Pure backward expressions whose
inputs are all available during forward can themselves become residuals. This
allows a boolean predicate to be generated in forward even when the original
forward program did not compute it.

After selection, lowering generates two independent HIR functions. Forward
returns its ordinary outputs and selected residuals. Backward accepts only the
external values it uses and those residuals, and reconstructs the rest. The
functions are checked by TileFoundry, evaluated on CPU, and analyzed for compute,
memory, roofline, and modeled performance. The phase boundary stays explicit.

## Results

All listed residual searches returned `OPTIMAL`. The frontier consists of the
nondominated results among the budgets sampled, rather than an enumeration of
every possible Pareto point.

### MLP

For `Z=XW; H=ReLU(Z); Y=HV`, with shapes `[8,16]`, `[16,32]`, and `[32,8]`, the
planner automatically chooses H under a 1,024-byte budget and uses the mask recipe
that avoids reconstructing Z. Without that recipe, the same search chooses Z and
reconstructs H. Both cases are checked against exhaustive search.

| Plan selected by the solver | Residual bytes | TileFoundry backward FLOPs |
|---|---:|---:|
| Recompute from inputs | 0 | 33,536 |
| Save H, derive its mask | 1,024 | 25,088 |

### Synthesized predicate

For `Y=sum(ReLU(XW))`, backward needs the sign predicate but not the full hidden
activation. Under a 256-byte budget, the planner adds the boolean predicate to
forward's outputs and saves it. The candidate program is generated by the search.
A boolean occupies one byte here; the implementation does not bit-pack masks.

| Plan selected by the solver | Residual bytes | TileFoundry backward FLOPs |
|---|---:|---:|
| Recompute from inputs | 0 | 25,088 |
| Generate and save boolean mask | 256 | 16,896 |

### Chunk gated delta rule

The convention follows the scalar gated delta recurrence described by the
[Gated DeltaNet paper](https://arxiv.org/abs/2412.06464) and
[FLA's reference](https://github.com/fla-org/flash-linear-attention/blob/main/fla/ops/gated_delta_rule/naive.py).
The state has shape `[K,V]`; `g` is the supplied scalar log-decay and beta is the
supplied activated update gate. Query scaling is `1/sqrt(K)`. The token recurrence
used only as an independent validation oracle is:

```text
D_t = exp(g_t) S_(t-1)
u_t = beta_t (v_t - k_t D_t)
S_t = D_t + outer(k_t, u_t)
o_t = (q_t / sqrt(K)) S_t
```

The synthesized program uses actual chunk matrix equations. For a chunk, with
`c=cumsum(g)`, `d=exp(c)`, and lower-triangular `E_ij=exp(c_i-c_j)`:

```text
L     = strict_lower(beta * (K K^T) * E)
U     = (I + L)^-1 [beta * (V - d * (K S_in))]
M     = lower((Q_scaled K^T) * E)
O     = d * (Q_scaled S_in) + M U
S_out = exp(c_last) S_in + [exp(c_last-c) * K]^T U
```

Upper-triangular log differences are masked before exponentiation to avoid
overflow from strong negative decay. A partial final chunk uses its actual size.
Multiple chunks connect through explicit state values; their boundaries are
candidate checkpoint locations.

The supplied backward uses the implicit triangular-system adjoint:
`dR=(I+L)^-T dU`, `dL=-strict_lower(dR U^T)`, plus explicit derivatives of the
remaining equations. It returns gradients for **Q, K, V, g, beta, and S0**.
Both output cotangents, `dO` and `dS_final`, are supported.

For `T=10, C=4, K=3, V=2`, including a 2-token tail, the graph contains 387
nodes and 93 eligible residuals:

| Residual budget | Saved bytes | Backward FLOPs | Example automatic decisions |
|---:|---:|---:|---|
| 0 | 0 | 5,316 | Reconstruct from inputs |
| 128 | 128 | 4,612 | Retain the two full-chunk inverse matrices |
| 256 | 256 | 4,316 | Add U values and both internal chunk-boundary states |
| 512 | 512 | 3,924 | Add selected Gram matrices and other intermediates |
| 1,024 | 1,020 | 3,394 | Retain more gates and contraction results |
| 2,048 | 1,420 | 3,254 | Stop saving when extra storage no longer reduces work |

The larger `T=65, C=64, K=16, V=12` case contains 278 nodes and 72 eligible
residuals. Both selected plans passed every numerical case and full static analysis:

| Selected plan | Saved bytes | Backward FLOPs | Backward gmem placement peak |
|---|---:|---:|---:|
| Recompute from inputs | 0 | 6,782,183 | 239,508 bytes |
| Save the first chunk's inverse | 16,384 | 1,498,343 | 223,124 bytes |

The triangular inverse is decomposed into a finite nilpotent matrix polynomial
using doubling. Prefix sums use a constant lower-triangular matrix. These are
transparent fixed-size HIR decompositions, not tuned solve/scan kernels. They
determine these counts; the reduction is **not a measured GPU speedup** or a claim
about optimized FLA backward kernels.

## Validation

- **83 new pytest cases passed.** The existing 272 upstream checks from environment
  setup remain recorded separately; upstream TileFoundry source was unchanged.
- Search results match independent exhaustive enumeration of residual subsets
  and algebraic recipes for both small graphs across nine budgets each.
- Removing the ReLU-mask recipe changes the selected MLP residual.
- Chunk forward and all six gradients match an independent sequential recurrence
  in float64 across six shape configurations and nine boundary/input cases.
- A directional finite-difference check validates the supplied chunk VJP.
- Generated HIR passes float32 checks at chunk sizes up to 64, including a short
  tail, nonzero initial state, strong/zero decay, beta zero/one, zero keys, zero
  initial state, output-only gradients, and final-state-only gradients.
- **12 selected plans, 104 generated-program numerical cases, and 24 complete
  phase analyses** passed across four recorded experiments. Float32 tolerance:
  `rtol=atol=2e-5`. The largest observed chunk-64 gradient absolute discrepancy was
  approximately `1.72e-5`. This is numerical evidence, not a universal proof.
- Source formatting, import/lint checks, and shell/Python syntax checks passed.

The first 3-second allocation budget was too short for one larger unrolled
backward graph (217 roots and 10,344 interference constraints). The bounded
allocation timeout is now 15 seconds; all recorded phase analyses succeeded.
Residual-search status and physical-allocation status are reported separately.
TileFoundry's placement is feasible under its chosen traversal order, not a proof
of globally minimum peak storage.

## Current boundaries

- Budgets constrain **bytes retained between phases**, not total live memory.
  External inputs, constants, ordinary outputs, and transient backward buffers
  have their own costs. For example, the MLP saved-H plan has a slightly larger
  modeled backward gmem peak than its recompute plan. A smaller residual set is
  not automatically a smaller total peak; both figures remain in each report.
- The objective is elementary work: matmul is `2*M*N*K`, scalar arithmetic and
  exp/compare/cast count as one unit per element, and reductions count additions.
  TileFoundry's FLOP/other-operation accounting is reported independently.
  Hardware-calibrated runtime is not the solver objective.
- Inputs and ordinary outputs are assumed immutable and externally available.
  An explicitly mutable-input contract is rejected. Python mutation, RNG, aliases,
  and arbitrary user programs are not traced or imported.
- Shapes are concrete, matrices are FP32, and chunk loops are unrolled during
  graph construction. The model represents one independent sequence/head;
  batch/GVA, variable-length packing, fused gate activation, and BF16 training
  are outside this prototype.
- Each logical value is computed at most once in backward. There is no search
  over repeated local recomputation, temporal checkpoint schedules, kernel
  partitioning, layouts, tiles, fusion, or storage levels yet.
- Algebraic rules and forward/backward equations are supplied. General identity
  discovery, theorem proving, and new summary identities remain further work.
- Analysis uses the **H200 static model** and CPU HIR interpretation. No kernels
  were executed or timed on the devbox's L20D GPUs.

The next useful extension is to constrain the total scheduled live set and explore
tile-local recomputation/fusion using the existing per-phase analysis reports.
